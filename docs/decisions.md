# Decision log

Consequential implementation choices, newest phase first. Routine reversible choices stay in code; cross-phase consequences live here and in handoff.md.

## Phase 14 — Imported Postman scripts

- **Imported events reuse the native script model and inherited walker.** `listen: prerequest` and `listen: test` map to the existing ordered pre/post arrays; `execution.InheritedScripts` remains the single collection → folder → request ordering rule and filters disabled entries.
- **Provenance is also the runtime source label.** Imported script source, IDs and provenance stay unchanged; execution uses the provenance source/path for Goja diagnostics and falls back to the script ID for native scripts.
- **Static compatibility checks stay intentionally shallow.** Import reports obvious `pm.globals`, `pm.iterationData`, timer and module usage, but runtime guards/reference errors remain authoritative for dynamically reached APIs. Strict mode rejects the import warning; lenient mode stores the script and lets execution fail loudly if reached.

## Phase 13 — Postman data import

- **Import parsing is side-effect free and persistence reuses the store's atomic saves.** `internal/importer` decodes and normalizes the complete v2.1 tree before `SaveCollection`/`SaveEnvironment`; strict warnings therefore cannot leave partial files.
- **Native import metadata carries source recovery and execution blockers.** Full collection/environment JSON and unsupported request/folder context stay attached to imported data. Unsupported auth/body is represented as `none` only as a safe placeholder and the request is blocked before execution, so it can never silently become unauthenticated.
- **Disabled values are represented separately from active maps.** `disabled_variables` keeps imported values inspectable while `ActiveVariables` excludes them from interpolation; item/entry/script enabled state uses the existing native flags.
- **URL raw query wins duplicate representation.** Structured query entries already present in a Postman URL `raw` value are not appended a second time; distinct structured entries remain ordered native query entries. Path variables in structured URLs use supplied defaults, while absent defaults remain unresolved placeholders.
- **Collision policy is explicit.** Default collection/environment imports choose deterministic suffixes and emit warnings; an explicit `--name` collision fails before persistence. Strict mode treats every normalization or unsupported-feature warning as a no-write error.

## Phase 12 — Promise settlement and cleanup

- **Promise form reuses the Phase 11 auxiliary scheduler.** `pm.sendRequest(request)` creates a Goja Promise and stores its owner-only resolve/reject functions on the tracked task; the existing two-argument callback form remains unchanged. Host results never carry JS values across goroutines.
- **Promise reactions are flushed by the owner loop.** Goja drains jobs when `RunProgram` returns, but host completions happen afterward, so the owner invokes an empty script after each drain turn to run reactions that may mutate variables or schedule nested requests. A response adapter used as a Promise fulfillment value permits only the required undefined `then` probe; normal `pm.response` remains strictly guarded.
- **Unhandled rejection policy uses Goja's tracker.** Reject events are retained in owner state and removed on Handle events; after each Promise-job turn, the first remaining rejection fails the script. A network or auxiliary body-limit rejection with a catch handler therefore remains recoverable, while ignored/re-thrown chain rejections fail with a loud diagnostic.
- **Cancellation is context-first and generation-checked.** Script timeout, parent cancellation, skip and runtime errors cancel the per-entry context; active workers honor it, queued work is dropped, and owner delivery checks context/generation/skip before invoking callbacks or settling Promises. The pending counter is cleared when a run ends so late workers cannot affect a later run.
- **Timers/modules stay absent.** No `setTimeout`/`setInterval`/`require` shim is installed; Goja's source-located ReferenceError is the loud rejection for these deferred APIs, avoiding fake asynchronous behavior or filesystem/module access.

## Phase 11 — Auxiliary callback requests

- **`pm.sendRequest` is callback-only in this phase.** String URLs and the supported request object are normalized on the owner goroutine, then sent through `httpclient.Send`/`BuildBody`; Promise return/settlement remains Phase 12 work so an untracked Promise cannot finish a script early.
- **Auxiliary work uses a FIFO queue with 20 accepted requests and 4 active workers per script run.** The owner increments pending before enqueue/launch, workers return plain results through the owner queue, and only the owner invokes callbacks or creates response values. Generation checks discard late results after cancellation or a later run.
- **The callback response reuses the response adapter** (`code`, `status`, `responseTime`, headers, `json`, `text`, and the existing status assertion chain). HTTP status errors are responses; network/body-limit failures arrive as `err` with no response, and a callback that handles the error can continue. A thrown callback error fails the script.
- **Request objects accept `url` (string or raw/components/query object), `method`, `header` (ordered entries or string map), `body` modes raw/urlencoded/formdata text, and basic/bearer auth.** Variables resolve when scheduled; explicit Authorization wins; saved request headers/auth are never inherited. Formdata file fields and unknown object properties are rejected because JavaScript has no filesystem access.
- **Auxiliary response bodies are bounded at 10 MiB** and all worker contexts honor the execution context. `skipRequest()` cancels the run context immediately; queued work is dropped and late workers cannot invoke callbacks. The default auxiliary client follows the normal redirect limit with TLS verification enabled.

## Phase 10 — Tests and supported assertions

- **pm.expect is a JavaScript shim, not Go bindings.** The chain (to/be/have/and words, `not`/`deep` flags, equal, a/an, property, include, lengthOf, true/false/null/undefined getters) is defined in `expectPrelude` inside internal/scripting/assertions.go and evaluated once per engine at construction — JS gives native `===`/`typeof`/`in` semantics for free, which is exactly what "do not implement loose equality as strict equality accidentally" needs. Go only bridges `pm.expect(actual)` to `globalThis.__reqExpect` and implements `pm.test` where the engine must record outcomes.
- **The chain is wrapped in a Proxy whose word getters return the proxy itself**, so a typo or unsupported Chai assertion (`.to.exist`, `.to.eql`, `.length`) raises `unsupported assertion .exist (supported: …)` instead of resolving to undefined and silently passing — matching the "never return fake successful values" rule. Symbol gets pass through untouched, same rule as the pm guards.
- **Assertion semantics (fixture-tested, Chai subset):** strict `===` by default; `deep` switches to structural equality over own enumerable keys (arrays ordered, key order irrelevant, extra keys matter, NaN deep-equals NaN while strict-equal fails). `a/an` accepts typeof names plus `array` and `null` (type-detect behavior). `property(name[, value])` requires an object/function target and uses `in` (prototype-inclusive; JSON data is own-only anyway). `include` is substring for strings, member for arrays (strict, or deep with the flag), key-subset with value equality for plain objects. `lengthOf` compares `.length`. Terminal assertions return a fresh chain with flags cleared so `.and` chains continue.
- **pm.test catches everything the callback throws** (assertion errors and runtime errors alike — Postman/mocha behavior), records `{Name, Failed, Error}` and continues; a pre-phase failed test never cancels the HTTP request. The skipRequest sentinel is rethrown untouched (detected via the engine's already-set `skipRequested` flag) so skip semantics are unchanged. An async callback (returns a Promise — covers `async function`) is rejected explicitly with `asynchronous test callbacks are not supported; the callback returned a Promise`, failing the script (exit 5) with no premature passing test; promise detection is `res.Export().(*goja.Promise)`, which has no Proxy-trap side effects on this goja pin (proxies export as the distinct `goja.Proxy` wrapper).
- **Failed-test messages come from the thrown Error's `message` property** (`testErrorText`): this goja pin's `Exception.Error()` appends the short stack on the same line (`"boom at f.js:2:38(pc)"`), so a newline cut alone would leak locations into `ID: FAIL name: msg` lines. The newline cut remains as fallback for exotic throwables.
- **pm.response.to.have.status(code)** is two guarded proxies over the existing response adapter (`pm.response.to` allows `have`; `pm.response.to.have` allows `status`), failing with `expected response to have status code N but got M`. Only the numeric subset is supported; `pm.response.to.be.success` etc. raise the standard compatibility error. Uncaught (outside pm.test) assertion failures fail the script normally (exit 5), matching Postman.
- **Exit code 6 and precedence:** failed assertions aggregate across pre and post phases; `preferAssertions` swaps 0/3/4 outcomes to 6 at every exit site (including transport failure after a pre-phase failed test and --fail 4xx), while 2/5/130 always win (5 > 6 verified: a post runtime error with a failed pre test still exits 5). Test results print to stderr per entry as `ID: PASS name` / `ID: FAIL name: message`, prefixed like script logs; stdout stays body-only. Structured output arrives with Phase 18.

## Phase 9 — Variables, request mutation and response APIs


- **Prepare split into MergeOverrides + ResolveRequest; Prepare survives as the composed wrapper.** MergeOverrides applies structural CLI overrides onto `scripting.ExecRequest` — the mutable execution copy with enabled saved entries flattened and the chosen Body struct deep-copied — before pre scripts run; ResolveRequest resolves variables in place on that copy afterwards, exactly the section 7 algorithm (overrides → scripts → final resolution). Pre-script mutations (headers, body.raw) and `{{references}}` feed the same copy; saved definitions stay untouched (verified byte-identical in tests). Generated Authorization/Content-Type append to a copied header slice so the copy keeps its exact pre-script shape.
- **Shared types live in scripting because the dependency points that way:** execution imports scripting (RunLifecycle creates the engine), so `ExecRequest`/`ResponseData` are exported from scripting and execution builds/consumes them. SetPreRequest/SetPostRequest are called by the lifecycle between runs, when no script can be on the stack — the owner goroutine is idle, so touching the runtime from the caller is safe.
- **pm objects are guarded by goja Proxies with sorted allowlists.** Unknown string properties anywhere on the pm tree (including console) raise `unsupported pm API "pm.x.y" at <script>:<line> (<phase> script; supported: …)` via `Runtime.CaptureCallStack`; symbol properties pass through (a throwing symbol trap would break type conversion and promise checks); property writes are rejected as read-only. Known-but-unavailable properties give specific errors: `pm.response` in pre scripts, `pm.request` with no view attached.
- **Variable semantics per section 7:** pm.variables.get/has walk the full precedence chain (CLI > local > environment > collection) and set/unset touch only the execution-local layer, so CLI overrides stay immune to script writes. pm.environment/pm.collectionVariables get/has read their own layer; set/unset on a missing environment layer fail with a --env hint. Missing-key get returns JS undefined; a stored null maps to JS null (goja's ToValue(nil) would say undefined). Values round-trip via Export (JS numbers become float64, matching JSON-loaded variables). All writes are in-memory only; persistence eligibility is preserved for Phase 17.
- **replaceIn is values-only and non-failing:** it recursively substitutes resolvable `{{refs}}` (same lookup as interpolation, including `env:NAME`) inside strings held by objects/arrays and leaves unknown placeholders intact — `Scope.ReplaceIn` is the shared primitive; ResolveString keeps its fail-on-unresolved contract.
- **Request mutation rules:** headers.add appends; upsert and remove replace/drop ALL case-insensitive matches; get/has are case-insensitive first-match reads. body is exposed only for inline raw/JSON (`raw` getter/setter over the execution copy's Text; a raw write on a JSON body can produce invalid JSON, rejected later by the existing resolution validation); file-backed bodies read undefined and writes name the file; other body modes are null. The post-phase adapter is a read-only view of the resolved outgoing request (final URL with queries; inline raw/JSON body shares the resolved text — a JSON body loaded from file becomes inline during resolution, a raw file upload stays undefined).
- **Response adapter is post-only and built from the buffered body:** code/status/responseTime(ms)/headers.get+has (canonical http.Header semantics, first value) and json() (descriptive parse failure) / text(). Accessing pm.response before the response exists stops the pre phase (exit 5) with a clear message; nothing is sent.
- **Console is bounded per run:** the first 1000 entries / 1 MiB are kept; the entry that would exceed a cap appends exactly one truncation notice and the rest is dropped. Constants, not configurable — ponytail ceiling; revisit only if a real script hits it.
- **pm.test/pm.expect/sendRequest are installed in the production allowlist.** Promise-based `pm.sendRequest` remains intentionally unsupported until Phase 12.

## Phase 8 — Script storage and inherited execution

- **One engine per execution, spike surface quarantined:** `scripting.NewEngine()` installs only `pm.execution.skipRequest()` and `console`; the Phase 1 spike globals (vars/log/httpGet/httpGetAsync) now live in a test-only file behind `newSpikeEngine()` so production scripts can never see them. The async host machinery (startHTTP/fetch) stays in production code — Phase 11 extends it.
- **Skip is a flag plus a catchable sentinel:** `skipRequest()` sets an owner-goroutine flag and aborts the running script by panicking with `rt.NewGoError(errSkipRequest)`. The flag survives a caught sentinel and wins over later runtime errors; phase enforcement (pre only) lives in the lifecycle, not the engine — a post-phase skip is reported as script failure (exit 5).
- **Lifecycle owns phase order; HTTP stays script-blind:** `execution.RunLifecycle` runs pre entries (collection → outer-to-inner folders → request, enabled only, per-entry 5s deadline via `--script-timeout`) before `Prepare`'s final interpolation, then `Execute` streams when no post scripts exist. With post scripts the body is buffered at 10 MiB (`MaxScriptBodyBytes`, a constant for now); over-limit exits 5 without post scripts or partial output. `dispatch` was extracted from `Execute` as the shared send prologue; Execute's behavior and signature are unchanged. Precedence implemented: cancel 130 > script 5 > transport 3 > --fail 4.
- **Script editing edits one combined source with explicit separators:** `req script edit PATH (--pre|--post)` renders `// ---- req script <ID> ----` lines; an edit must preserve the marker ID sequence exactly (count/order/value) or it is invalid and preserved in recovery. Enabled flags and provenance round-trip by ID; the other phase is untouched; zero entries plus non-empty marker-free text creates one enabled entry (a marker anywhere in new content is rejected — it would otherwise booby-trap the next edit). Stored sources normalize to exactly one trailing newline per edit. `UpdateScripts(path, *model.Scripts, expected Revision)` covers collection root, folder and request under the normal revision-checked save; `launchEdit` is the shared editor skeleton extracted from `editJSON` (request-edit messages unchanged).
- **Deferred by design:** response-buffer configurability, console caps (1000 entries/1 MiB in Phase 9), Promise-based sendRequest settlement (Phase 12), and splitting Prepare so structural overrides are visible to pre scripts (unobservable until Phase 9 exposes pm.request). `req send` takes no script flags — direct sends have no scripts.

## Review corrections after Phase 7

- `DeleteItem(ctx, path, expected Revision)` now requires the revision observed by the caller. Both request/folder deletion pass their resolved revision; a change during folder confirmation fails with a storage conflict and preserves the current tree.
- Runtime completions check their generation before decrementing pending work. Old canceled requests cannot prematurely finish a subsequent script on the same engine.
- Response-body cancellation returns 130, matching send-time cancellation. Explicit Host headers populate Go's Request.Host (first value), including saved variable references.
- Collection loads reject filename/ID mismatches without rewriting. Name uniqueness remains enforced under SaveCollection's lock; redundant create/rename scans were removed. Slice comparisons use slices.Equal.

## Phase 7 — File uploads and body formats

- **One body definition across CLI entry points:** `Overrides.Body *model.Body` replaces the byte/BodyMode pair; nil keeps the saved body. `send`, `run` and `request create` use the same body flag parser. `--body-file PATH`, `--json @PATH`, repeated `--urlencoded KEY=VALUE`, and repeated multipart `--form KEY=VALUE` / `--form-file KEY=PATH` are supported. Multipart text/file can mix; other body modes conflict. A leading @ in a form text value stays literal. Creation stores references without reading files.
- **Empty values:** Body.Text and MultipartField.Value are optional string pointers, so explicit empty strings survive JSON round trips and conflict with a simultaneous file reference. For compatibility, old raw objects with omitted text/file still mean empty inline content; nil/none means no body. Tag/payload mismatches are rejected. This resolves the Phase 3 representation question without a schema migration.
- **File bases and trust:** Saved runs (including CLI body overrides) resolve relative paths from the workspace root; direct sends resolve from cwd. Raw files and multipart attachments preserve every byte, including placeholder-like sequences. JSON file contents are buffered, interpolated once and validated before HTTP. Native absolute paths are explicit user input. Future importers must set `file_untrusted` on imported references; absolute/outside-workspace and symlink-escaping untrusted paths fail before access and can be remapped through editing.
- **Streaming and replay:** The HTTP body builder stores multipart framing/text and file paths as segments. Open streams through io.MultiReader with a known content length; no pipe or producer goroutine exists. Files open before network access and close idempotently on completion/error/cancellation. Request.GetBody reopens independent readers for 307/308 redirects; empty bodies replay as http.NoBody. The file size is checked again on open; attachments are read live, not snapshotted. Large attachment counts hold one descriptor per attachment; JSON input remains buffered.
- **Content types:** Defaults are text/plain for inline raw, application/octet-stream for raw files, application/json for JSON, application/x-www-form-urlencoded for encoded forms, and multipart/form-data with a generated boundary. Explicit headers win except that multipart must have one compatible Content-Type with a matching boundary; a missing boundary is added, a valid supplied boundary is used. Native multipart JSON supports filename/content_type overrides. Control characters in part metadata fail validation.
- **Verification:** The Phase 7 checkpoint records loopback uploads, replay, zero-network invalid requests, streaming/cancellation/close checks and Windows symlink containment. No dependency added.

## Phase 6 and prerequisite audit — 2026-09-12

- **Environment schema:** `{schema_version: 1, name, variables}`; variables are JSON values. Filenames use 1–64 ASCII letters/digits/underscore/hyphen and reject Windows device names. This portable subset excludes spaces/punctuation. Unknown fields, future versions, filename/name mismatches and reserved `env:` keys fail. Writes reuse lock/hash/atomic replacement and use 0600 where supported; gitignore is not encryption. Disabled imported values remain Phase 13 work.
- **Variables:** CLI strings (last repeated key wins) > local map > environment > collection. Missing differs from null. Strings interpolate directly; other values use compact JSON. One pass only; remaining placeholders fail with field location. Only explicit `{{env:NAME}}` reads the process environment. Phase 9 must keep CLI overrides inaccessible to script setters.
- **Auth:** Resolve nearest explicit collection/folder/request auth while walking the stored path, then apply CLI auth to the execution copy. Explicit Authorization wins, so unused inherited credential references need not resolve. Basic credentials must be supplied together; usernames containing a colon fail. Modes are exclusive. Request creation saves auth references verbatim.
- **Editor correction supersedes Phase 5's whitespace-only limitation:** quoted executable paths/arguments are grouped without shell evaluation; backslashes remain literal for Windows paths. Request/environment edits share strict decode, revisions and recovery; if conflict recovery fails, the temporary edit remains and is named. Shell expansions and shell escape syntax are not supported.
- **Audit corrections:** query placeholders and saved JSON validate at the final request boundary. Native JSON requires EOF after the document. Collection name uniqueness is enforced under SaveCollection's lock after revision validation, preserving future-schema conflict precedence. See req-iterative-plan/verification.md.
- **Script sequencing:** ordered script models already exist. Phase 8 reuses the owner loop and introduces response limits before response APIs; Phase 11 extends it for auxiliary work. These prerequisites cannot wait for Phase 18 output modes.

## Phase 5 — Editing and organizing requests

- **`UpdateRequest` takes the caller's source revision.** The first cut loaded the collection internally and saved against that fresh revision, which would have let a long editor session silently overwrite a competing save (exactly what the storage contract forbids). Now `UpdateRequest(path, req, expected)` forwards `expected` to `SaveCollection`, whose under-lock reread/compare is the single authoritative check — the CLI keeps no pre-check of its own, so there is no check-then-save window. An editor conflict therefore produces `*ConflictError` (exit 7) with the rejected candidate preserved in `.req/recovery/`.
- **`request edit` edits only the `request` payload** (the exact JSON `request show` prints, strict-decoded with unknown-field and trailing-data rejection). `name` and `id` are identity, managed by `rename`/`move`; IDs survive rename/move per the storage contract. Unchanged bytes → no write at all. Invalid JSON → the edit is preserved via the now-public `store.SaveRecovery` (extracted from `conflict()`, same naming and 0600), exit 2. Editor failure → the temp `req-edit-*.json` is kept and named (nothing else preserved the edit yet).
- **Editor launch is shell-free by spec:** `$EDITOR` beats `$VISUAL` (blank values count as unset; both unset → setup instructions, exit 2); the value is whitespace-split into argv and executed via `exec.Command`. Consequence: editor arguments containing spaces are not expressible (a quoted `sed` expression breaks) — such editors must be wrapped in a script. Verified by a real smoke launch (`EDITOR="sed -i s/GET/PUT/"`).
- **Move semantics:** `move SRC DEST` — DEST names the destination *parent* (existing folder or single-segment collection root); the item keeps its name and ID and is appended as the LAST child. Same-parent move = no-op (no write, and checked before the cycle test so it is not misread as a cycle). Cycle rule: destination item-segments having the source item-segments as a prefix (equal or longer) → `ErrBadMove` → exit 2. Cross-collection detection is lexical on the first segment (fires even when the other collection does not exist); the cycle check likewise fires before destination existence is resolved.
- **Deletion semantics:** nonempty folder/collection requires `--yes` or an interactive y/N on a terminal stdin; EOF/decline prints "deletion aborted" and exits 0 with nothing deleted; non-terminal stdin without `--yes` exits 2 with a pointer to `--yes`. Empty folders/collections and single requests delete without confirmation (`--yes` is accepted on `request delete` for symmetry). `DeleteCollection` checks the caller's revision under the workspace lock before `os.Remove`; a conflict carries no recovery file (a delete has no candidate content). Confirmation hooks (`stdinIsTerminal`, `confirmDelete`) are package vars so tests never need a pty.
- **Exit-code mapping extended:** `ErrBadMove` joins the sentinels mapped to 2 in `usageOrStorage` — a bad move is a usage problem, not storage damage.

## Phase 4 — Collections, folders and saved requests

- **Slash paths address collections by Name, not ID.** The CLI contract (`req tree "My API"`, `req run "My API/Auth/Login"`) is name-based; duplicate collection names are therefore rejected at create (`ErrDuplicateName`), making names unique keys. Name resolution (`collectionByName`) strict-loads every collection file, in sorted-filename order — deterministic and honest about malformed files (they fail the command with exit 7 rather than being skipped).
- **`--parents` creates missing ancestor folders only, never the collection.** A missing collection is always "not found" (exit 2); collection creation stays the dedicated `collection create` command. Request create accepts `--parents` too (the spec's rule "creating missing ancestors requires `--parents`" is generic, not folder-specific).
- **One execution path for send and run.** `internal/execution.Prepare(saved, overrides, policy)` + `Execute` is the single send/render core; `runSend` and `runRun` both go through it. Overrides are structural only (`method/url/body` replace; `header`/`query` entries **append after** saved ones — matching §3's "repeated query/header flags append entries"); HTTP policy (timeout/TLS/redirects/fail) is a separate `Policy` struct so callers can't accidentally leave redirects off (the CLI default is follow). `run` never writes the collection file back.
- **Remaining `{{…}}` placeholders fail execution with exit 2 — including direct `req send`.** Substitution arrives in Phase 6+; until then any placeholder in method/URL/headers/body is "unresolved" and a literal placeholder is never put on the wire. This deliberately tightens Phase 2 behavior (a `{{…}}` in a send URL used to be sent literally); `Prepare`'s placeholder check is what enforces it for both entry points, and the error names the placeholder and the field.
- **`--json` validation timing follows §3:** validated immediately at `request create` / `run` parse time only when the text contains no `{{` (placeholders may make it valid JSON only after substitution; then it is stored/passed verbatim). Placeholder-free invalid JSON stays a usage error (exit 2) at the earliest opportunity.
- **Exit-code split for store-backed commands:** `ErrNotFound`/`ErrInvalidPath`/`ErrDuplicateName` → 2 (usage/lookup), everything else from the store (IO, lock, `*ConflictError`, malformed file) → 7. Model-level validation errors carry no sentinel, so handlers pre-validate the user-facing ones (collection name, method token, non-empty URL, entry shapes) to keep them at exit 2. Concurrent creates both load the same revision → the loser gets `*ConflictError` (exit 7) with a recovery file, per the storage contract.
- **Output channels:** CRUD status messages go to stderr; `collection list` (`NAME\tID`), `request list` (`NAME\tMETHOD\tURL`), `request show` (indented JSON of the stored request) and `tree` go to stdout so they pipe cleanly. Sibling order is always stored (insertion) order — "stable" means stable across invocations, not sorted; only `collection list` sorts (by name, because directory order is not stable).
- **Tree format:** root line (collection or resolved folder name), children flush-left beneath it, one 2-space indent per deeper level; folders render `Name/`, requests `Name  METHOD URL`. Requests-as-leaf details keep the tree useful without a second command.

## Phase 3 — Workspace and atomic persistence

- **Native schema shape:** items are tagged `{"type":"folder"|"request","id","name"}` with an exclusive `folder`/`request` payload object (flat enough to eyeball, unambiguous to validate). Entries are ordered `{key,value,enabled}` lists; `Auth`/`Body`/`Scripts` are tagged structs; nil `Auth`/`Scripts` mean "not set" (= inherit for items). Strict decode (`DisallowUnknownFields` + trailing-data rejection) is the enforcement point for "unknown fields must be rejected rather than silently discarded" — all loads go through `LoadCollection`, never a bare `json.Unmarshal`.
- **Names reject `\` as well as `/`.** The spec names `/` only, but Windows treats backslash as a path separator; accepting it would let an item name escape its directory there. Duplicate sibling names are rejected across types; IDs must match `[A-Za-z0-9_-]{1,64}` (also the filename-safety rule).
- **Revision = SHA-256 of the exact file bytes** (opaque to callers). Saving requires the loaded revision back; a missing expected revision on an existing file is also a conflict, so nothing can blindly overwrite. Conflict path: the rejected candidate is preserved under `.req/recovery/<id>-<hash>.json` (0600) and the error names it — this is the "recovery path" the storage contract requires.
- **Lock choice:** `github.com/gofrs/flock v0.13.1` (MIT) over `.req/.lock`, acquired with `TryLockContext` (honors ctx cancellation; 50 ms retry). The lock covers reread → compare → atomic replace. Verified by tests: 8 concurrent same-revision writers yield exactly 1 winner; a save cannot complete while another holder has the lock.
- **Atomic replace:** temp file in the destination directory (`.name.tmp-*`), write → `Sync` → `Close` → `Chmod` → `Rename`; failed attempts remove the temp and never touch the destination. Applied to collections, config.json and .gitignore alike.
- **`req init` accepts `--workspace` before or after the subcommand** (a smoke test caught the trailing form failing). For commands with value-taking flags (`send`), global flags are still only recognized before the subcommand so they can never be swallowed as a flag value.
- **Deferred representation question (Phase 7):** raw/JSON bodies with neither `text` nor `file` currently validate (empty string + omitempty makes "explicitly empty" ambiguous on disk). If empty-vs-absent must round-trip, switch `Body.Text` to `*string` then; noted here so it is a conscious choice.

## Phase 2 — HTTP methods, bodies and failures

- **Credentials follow redirects only within the exact origin (scheme + host + port), stricter than net/http.** Verified against the Go 1.25 source: `Client.do` compares domain names (`isDomainOrSubdomain` over IDNA hosts), so the stdlib forwards `Authorization`/`Cookie` across ports and on an https→http downgrade to the same host. Our `Client(Options).CheckRedirect` deletes the sensitive header set (`Authorization`, `Proxy-Authorization`, `Cookie`, `Cookie2`, `Www-Authenticate`, `Proxy-Authenticate`) whenever the redirect leaves the original origin, and keeps them on same-origin redirects. Subdomain forwards are also stripped (no `--location-trusted` equivalent until a phase asks for one); explicit `:80`-style ports are compared literally, so a default-port URL may be over-stripped — the fail-safe direction. This behavior applies to main and (later) auxiliary script requests because both use `httpclient.Client`.
- **Client policy moved into `Options`/`Client(opts)`** (`internal/httpclient/build.go`); `DefaultClient()` = `Client(Options{})`; `Send` untouched. Phase 3+ selects per-execution policy (timeout, insecure, redirects) through `Options`.
- **Send flag parsing is strict and additive.** Repeated `-H/--query` append entries; `--query` appends onto the existing URL query without re-encoding it (duplicates and empty values survive byte-for-byte). `--body`/`--json` are the only body modes until Phase 7; JSON is validated (exit 2) before sending; generated Content-Type (`application/json` / `text/plain`) loses to any explicit `Content-Type` header. Positional `METHOD URL` and `--method`/`--url` are mutually exclusive; unknown flags and extra positional arguments exit 2.
- **Go 1.25 renamed the redirect sentinel:** `http.ErrUseLastResponse` (the old `ErrUseOfLastResponse` no longer exists) — used for `--no-follow`.

## Phase 1 — Embedded JavaScript feasibility

- **Runtime chosen: `github.com/dop251/goja`, pinned at `v0.0.0-20260903201622-f87b40ad7341`.** Resolved via `go get @latest` on 2026-09-05 with Go 1.25.5; commit dated 2026-09-03, so the project is actively maintained. License: MIT (verified in the module cache). All five feasibility tests pass under `-race`.
- **Goja fact that shapes the event loop:** this version has no `ExecuteDeferredJobs`; promise reaction jobs run automatically whenever the JS stack empties — after `RunProgram` and after each owner-thread `Callable` invocation. The drain loop therefore only needs the pending-host-task counter; reactions that schedule more host work raise the counter again before the check.
- **Interrupt handling:** `rt.Interrupt` is the only cross-goroutine runtime call (watchdog only). It latches if the runtime is idle, so each run starts with `ClearInterrupt()` — safe because the previous run's watchdog has provably exited before `Run` returns. `Run` reports either `*goja.InterruptedError` or the context error for the same cancellation; tests accept both, and the production exit-code mapping (130/3) is applied later.
- **Late completions:** every completion job carries the run-generation token of the run that scheduled it; if the run has ended (or its context is gone) the job is discarded without touching JS values. `Close` drops queued jobs via a `quit` channel so senders never block or panic.
- **Spike bindings (`vars`, `log`, `httpGet`, `httpGetAsync`) are throwaway.** They prove ownership/interruption/async only; the supported pm surface is built in Phases 8–12 and is not wired into the CLI yet. Spike body cap is a fixed 1 MiB placeholder; the configurable 10 MiB policy comes with production bindings.

## Phase 0 — Core / Walking Skeleton

- **Module path is `req`, module rooted at the repository root.** No hosting/domain prefix; the binary is the deliverable and nothing is published. Imports read `req/internal/...`. No third-party dependencies yet.
- **Argument parsing is strict positional parsing inside `internal/cli`, not the `flag` package yet.** `req send METHOD URL` must be exactly two arguments; anything else (unknown command, missing/extra args, schemeless or non-http(s) URL) exits 2 with usage. Nothing is silently dropped; flags join in Phase 2 ("keep argument parsing replaceable").
- **A status/duration line goes to stderr on every successful send** (`GET url -> 200 OK in 1.2ms`), per IMPLEMENTATION.md §6 ("stderr contains status, elapsed time"). Stdout stays body-only.
- **Context cancellation maps to exit 130** (`signal.NotifyContext` in main; `runSend` checks `ctx.Err()` after a Send error). Transport errors otherwise map to 3; body-read failure after received headers also maps to 3.
- **`httpclient.Send` rejects non-http(s) schemes defensively** even though the CLI already validates (exit 2 first). The CLI check owns the user-facing message.
- **`Version = "0.0.1"` is a constant in `internal/cli`**; `--help`/`help` prints usage to stdout with exit 0. Build-info stamping deferred; trivial to add at delivery.
- **No VCS initialized.** The directory was not a git repository and none was requested; handoff.md tracks working-tree state instead. Initialize git whenever the user wants per-phase commits.
